## 4. 认领规则

1. **先看依赖是否满足**：查 [任务索引](../tasks/index.md) 的"硬依赖"列，依赖没合并前不正式开始（可用 fake 提前开发）。
2. **优先走自己板块主线**：默认接角色表里的下一个 Issue，除非它卡在别人的依赖上。
3. **卡住就转支援，不空等**：去做可用 fake 提前开发的部分，或认领 Q 板块的通用证据工作（A/B 回放、证据落盘、文档/ADR）。
4. **认领以 GitHub Issue 为准**：打开对应 Issue 确认"未分配 + 状态最新"，更新 Assignee；分支、PR、完成条件按 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
5. **交叉复核**：功能完成不只是自己通过，还要找另一板块的人复核，复核通过才算关 Issue。
