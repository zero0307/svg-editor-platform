# 交付风险清单

> 状态：交付前的风险自查清单，与 [开发规范](2026-11-16-development-conventions.md) 配套使用。用于在"代码完成"之后、正式提交之前逐项核对，避免把工程完成误当成课程交付完成。
>
> 使用方式：每个里程碑收口和最终 `p2` 发布前各核对一遍；"检查时机"标注的是最早可验证的时间点，不是可以拖延到最后的理由。勾选状态在 GitHub Issue / PR 中维护，本文件不另抄一份完成状态。

| 风险等级 | 含义                                       |
| -------- | ------------------------------------------ |
| 🔴 致命  | 不可逆或导致整门课程交付失败，必须最先解决 |
| 🟠 高    | 会引发大面积返工或验收不通过               |
| 🟡 中    | 影响单项验收证据，可定位修复               |

## 1. 课程交付路径（🔴 最高优先级）

| 风险项                                                                          | 检查时机               | 责任板块 | 失败后果                                              |
| ------------------------------------------------------------------------------- | ---------------------- | -------- | ----------------------------------------------------- |
| 最终交付须同步回**原仓库** `zero0307/svg-editor-cli`，新仓库只是日常协作        | 开发期间就明确交付地址 | Q        | 只在协作仓库交 = 未满足"远程仓库（同一个）"，整项作废 |
| 同步前 fetch 原仓库最新 main，有改动先合并再验证，**禁止 force push 覆盖**      | 每次准备同步时         | Q        | 覆盖原作者/历史，违反"保留历史"红线                   |
| `p2` 在新旧仓库**指向同一提交**，`final` 永久不变                               | 打 tag 前              | Q        | 交付版本不一致，评阅无法复现                          |
| 课程平台上传 [submission/README.md](../submission/README.md) 并验证**匿名访问** | 最终提交时             | Q        | 教师/助教打不开仓库，直接判未提交                     |
| 核对课程平台**截止时间**（需求文件未注明日期）                                  | 开工即确认             | Q        | 错过截止                                              |
| 第三部分 **DSH 验收深度**向教师确认后再定稿                                     | DSH 板块开始前         | D        | 自以为完成的部分与课程实际要求不符                    |

## 交付前总核对顺序（建议）

```text
1. 课程交付路径（原仓库 + p2 + submission README + DSH 歧义）→ 先确认，不可逆
2. 指标口径（final→p2、迁移表、SHA 对齐）→ 收尾最容易返工
3. A/B 证据当场留 SHA → 历史补造即作废
4. CI/分支保护真实落地 → 保护门槛成立
5. 逐字节兼容细节 → 避免 golden 污染
6. 技术坑 + 环境 + ADR → 单项验收扫尾
```

> 本清单是"风险"清单，不是"完成"清单；每项都要能指出对应证据文件、提交 SHA 或 Issue 链接才算关闭，不能只口头确认。
