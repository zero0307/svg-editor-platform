# 桌面点选与同名节点改名验收

2026-11-25 在 macOS 的 DeepSeek Harness Desktop 0.2.2-rc.5 上，用同一账号、标准模式和 DeepSeek-V4.1-Flash High 实测。每一个目标都开启新会话，在同一目录从同一份 35 节点、40 条连线的 Transformer 原图开始。五个框的首行都是 Add & Norm，副标题也相同。[测试原图](../evidence/dsh/local-edits/before.svg)

## 验收方法

- 点选组在右侧工作区打开 SVG，把与盲测完全相同的自然语言指令放入草稿，再实际点一个框并发送。会话记录里必须出现插件生成的选区引用。模型自行决定工具和操作。
- 位置描述组在同一桌面 profile 关闭插件，确认右栏恢复内置图片预览。在自然语言里把「我在预览里点的这个」替换为每个目标的唯一位置，例如「右边解码器里最上面的那个」。其余指令相同。日志核对两组实际使用的模型和插件调用。
- 每轮要求把目标第一行改为「课堂重点」，保留原件，另存 result.svg，读回后报告。验收器从原件独立构造只替换目标文本的期望字节串，用它与磁盘文件全文比较。每轮产物移出工作区后才启动下一轮。
- 耗时采用宿主同一轮的 `turn/start` 至 `turn/end`，不含打开文件、点选或输入位置所需的人手时间。token 为这一轮所有模型步骤的用量之和，包含缓存读取；费用还取决于缓存计价。成功率按独立首轮计，其余指标取每组五轮的中位数。

## 桌面实测结果

| 输入方式                       | 首轮精确改对 | 耗时中位数 | 总 token 中位数（含缓存） | 输出 token 中位数 | 工具调用中位数 |
| ------------------------------ | -----------: | ---------: | ------------------------: | ----------------: | -------------: |
| 无插件，写明唯一位置           |          5/5 |   19.53 秒 |                   193,097 |             2,242 |             11 |
| 0.9.1 点选，引用文件与节点 ID  |          5/5 |   14.41 秒 |                   146,977 |             1,920 |              7 |
| 0.9.2 点选，带标签与单节点读回 |          5/5 |    8.13 秒 |                    76,872 |               875 |              5 |

0.9.2 相对无插件位置组，中位耗时少 11.40 秒（58.4%），中位总 token 少 116,225（60.2%），中位输出 token 少 1,367（61.0%）。五次都从真实消息中取得正确选区，调用编辑工具时使用了被点框的 ID 和框内行号 1。独立读回五份结果，均为 35 个节点、40 条边、零条导入警告，只有目标标题的字节发生变化。

## 只说「这个」时的差异

11 月 24 日的同图无插件独立盲测，五个目标收到相同指令，选区信息没有进入消息。首轮 0/5，三轮未生成文件，两轮改中了另一个框。11 月 25 日在原生桌面预览实际点击解码器上方节点后又复测了一次；发送记录仍只含自然语言。模型尝试到工作区外查找 Harness 会话信息，测试者手动停止该轮。当时已用 100.98 秒且未生成结果。这次中止单列，不计入完成组的速度与 token 统计。

## 开发中发现的问题与复测

0.9.0 的桌面试跑中，模型一度把行号理解为整份 XML 的行号。0.9.1 将参数改为 `labelLine`，指明它从选中框的第一行起算。真实对话还出现重复读取整图的情况；0.9.2 将简短的当前标签随选区传入，给 `svg_inspect` 增加按节点读回，并在编辑结果里提供主文件 SHA-256 和原件读回状态。

在项目根目录可用下面的命令独立复核所附产物。把末尾两个参数换成相应的节点 ID 和产物路径即可复核其他轮次。

```sh
npm run build
node apps/dsh-plugin/verification/selection-result.mjs d_an3 doc/evidence/dsh/desktop-selection/result.svg
```
