## 0. 三条元规则

1. **契约先行**：公共接口先出契约 + 测试替身，评审进 `main` 后，其他板块才能依赖它开发。
2. **按板块交付，不按人绑定**：一个板块可结对，一人可兼两个低耦合板块；公共文件由专人协调。
3. **计划 ≠ 实现**：目标目录、拟建命令、未来检查都不能当成"已完成"；没跑的测试如实写"未执行"。

## 1. 技术栈与代码风格

| 项        | 规定                                                                   |
| --------- | ---------------------------------------------------------------------- |
| 语言/模块 | TypeScript **strict** + **ESM**                                        |
| 代码组织  | 面向对象、**一类一文件**、类名与文件名一致、字段封装                   |
| 测试框架  | 沿用现有 `node:test`，**不更换**                                       |
| 运行环境  | 团队统一 **Node 24 LTS**；DSH 下限 24.9.0；CLI 可另保 Node 22 兼容检查 |
| 工程      | npm workspaces，包名建议 `@svgframe/*`                                 |
| 依赖      | 保留现有版本以锁文件为准；迁移工作区时**单独提交**构建变化             |

**核心代码纪律**：

- 命令的"是否只读 / 是否需要文档 / 历史策略"用**元数据**表达，不得在 router 按命令名列白名单。
- 处理器只改事务工作副本；成功一次提交，失败不改文档 / dirty / undo / redo。
- 保留 Phase 1 输出和顺序，不随手改 golden 文件。

---

## 2. 架构与依赖方向

一句话：**内核只依赖公开抽象，插件只通过内核公开 API 注册能力，谁也不反向依赖、不跨包走相对路径。**

| 模块                     | 可以依赖                      | 禁止依赖                                  |
| ------------------------ | ----------------------------- | ----------------------------------------- |
| `core`                   | 自身公开领域抽象              | host、builtins、plugins、Node fs、XML DOM |
| `builtins` / `plugins/*` | **只** core 公开入口          | core 内部路径、其他插件、host、Node fs    |
| `svg-xml`                | core 公开端口 + XML 库        | 具体图形/命令插件、VSCode API             |
| `host`                   | core 公开入口 + Node 模块     | 具体插件（不得硬编码插件名）              |
| `apps/cli`               | host、svg-xml、core、builtins | 不得反向导入 core                         |

红线：

- 插件名不硬编码进内核、加载器、渲染器、codec（不出现 `if (kind === 'box')`）。
- 每个包用 `exports` 限公共入口，禁止跨包相对路径读 `src/`（架构检查脚本强制）。
- `box` 通过公开 `ShapeCreationService` 创建 rect/text，不直接 import 具体类。

## 3. 四扩展点与一次事务

| 扩展点             | 作用                        | 无实现时行为                         |
| ------------------ | --------------------------- | ------------------------------------ |
| `ShapeProvider`    | 创建 / 恢复图形             | 未知图形报错；无 box 时按普通 g 降级 |
| `Command`          | 命令（名称/帮助/校验/效果） | `error: unknown command: <name>`     |
| `TreeDecorator`    | 树行尾标签                  | 零后缀，Phase 1 树输出逐字节不变     |
| `AttributeHandler` | 属性在某图形上的语义        | 走原形状属性白名单                   |

**一次编辑事务**：

```text
解析参数/前置条件 → 多态 clone() 候选文档 → 在候选上执行 → 全量校验
（ID 唯一、无环、父子链接、不变量）
→ 全部成功才一次性替换 + undo 入栈 + 清 redo + 发事件
→ 任一步抛错：丢弃候选，文档/路径/dirty/屏障/undo/redo 全部不动
```

禁止：clone 用 encode→decode 做撤销快照；undo/redo 重跑可能带副作用的处理器。

## 4. 分支、提交与 PR

| 分支类型            | 示例                                                   | 说明                         |
| ------------------- | ------------------------------------------------------ | ---------------------------- |
| 功能                | `feat/023-plugin-dir`                                  | 一个可独立验收的功能         |
| 修复/测试/文档/工程 | `fix/041-*`、`test/036-*`、`docs/012-*`、`chore/008-*` | 编号对应 Issue               |
| 演示证据            | `evidence/box-code`、`evidence/box-config`             | A/B 证据，**保留到验收结束** |

- 只设 `main` + 短期任务分支，不设 develop、不按人建永久分支。
- 一个分支一个任务，1~3 天合并；大任务先拆契约 / 通用 / 插件 / 验证。
- 提交格式 `type(scope): 具体变化`；一次提交 = 一个可说明、可验证的变化。
- PR 一律 **merge commit**；**禁用 squash / rebase 合并**，不强制线性历史。
- 个人分支可 rebase；协作分支、evidence 分支不得改写；不 force push 到 main。

---

## 5. Issue 与完成定义

- 状态机：`Todo → In progress → In review → Done`；受阻标 `Blocked` 并写明所需决策。一人通常只同时推进一个主任务。
- 标签：`area:*` + `type:*` + `priority:*`；P0 只给阻塞主线的缺陷。
- PR 至少一位**非作者**评审；公开接口、历史回滚、loader 改动由内核/宿主负责人复核。

**一个功能"完成"须同时具备**：

1. 对应需求 ID；
2. 实现 + 公开契约；
3. 必要的成功**和失败**测试；
4. 更新的文档 / ADR；
5. 可定位的验证结果；
6. **另一板块的复核记录**。

---

## 6. 测试与验收

- **测试分层**：内核契约（假插件）→ 单插件（替身）→ 真实适配器（临时 fs）→ 宿主集成（编译后 CLI）→ 用户可见效果（真实 VSCode/dsh）。
- **契约先行才能并行**：M1 提供最小 fake context + 契约测试，插件据此独立开发；box 单测不依赖先激活其他插件。
- **两个"不能"**：不能删旧测试换新测试；不能最后补造 A/B / loader 回滚 / 零内核改动证据。
- **逐字节兼容**：禁用全部可选插件时，与 `final` 输出逐字节一致；stdout / stderr / exit code 分开比，不 trim、不排序。
- **失败状态不变**：至少测"已有 undo 历史"和"已有 redo 历史"两种前置状态，故障后逐项比较只读视图并实际 redo/undo。

---

## 7. 协作与分工

- 按板块认领（F/C/B/T/V/D/Q），Q 由集成协调者组织、共同承担。
- 接口变更走 Issue：先说明影响，**同时更新契约 + 替身 + 消费者 + ADR**。
- 根配置（根 package.json、锁文件、tsconfig、构建入口）由协调者合入，避免并行冲突。
- 插件缺通用能力 → 提独立框架 Issue，不穿透私有模块、不加插件名分支。
- A/B 证据：从共同框架基线 `F` 建两个 evidence 分支，`C_A` 只加插件 + 改一个组合根，`C_B` 只加插件 + 改配置，留完整 SHA 与 `git diff --name-status C^ C`。

## 8. 文档与记录

| 内容               | 唯一位置                            |
| ------------------ | ----------------------------------- |
| 课程报告入口       | `doc/README.md`                     |
| 架构 / 依赖规则    | `doc/architecture.md` + `.puml`     |
| 任务状态           | GitHub Issues（不在仓库另抄状态表） |
| 需求↔验收映射      | `doc/acceptance.md`                 |
| 设计决策           | `doc/adr/`                          |
| 关键过程 / AI 纠错 | `doc/records/`                      |
| 验收证据           | `doc/evidence/<milestone>/`         |
| 指标               | `docs/metrics/`（脚本生成，不手填） |

- ADR 状态机：`Proposed → Accepted → Superseded`，被替代的保留原文 + 链接后继。
- AI 协作记录须含"建议 → 检查 → 发现 → 修正 → 验证"，只写"AI 生成后测试通过"不算。
- 证据可复现：记录命令、cwd、Node/npm/DSH 版本、被测 SHA；截图不能替代事务/回滚测试。

## 9. 红线清单（速查，碰了就返工）

1. 移动 / 删除 / 复用 `final` 标签，或 force push 到 main。
2. 把目标目录、拟建命令、未来检查当成"已完成"写进报告。
3. 插件名硬编码进内核 / 加载器 / codec。
4. 删除旧测试，改用只覆盖新实现的测试替换。
5. 等全部实现合 main 后补造 A/B 接入历史（`C_A`/`C_B` 必须是当次接入的原始提交）。
6. clone 用 encode→decode 做撤销快照。
7. 为让 diff 通过而改 golden 文件；与课程要求冲突先建 Issue 记录裁决。
8. 提交访问令牌、Cookie、代理配置等敏感信息进仓库。

---

## 一句话总纲

> **契约先行 → 按板块并行（靠替身）→ 每次提交自带测试和文档 → PR 合并且保留历史 → 失败状态可证明不变 → A/B 与逐字节证据当场留 SHA → 计划与实现、真实结果与描述严格分开。**
