# ADR-0015 内容脏状态、祖先传播与标签顺序

状态：Accepted  
日期：2026-11-25  
关联：Issue #20（TASK-TREE-01）；需求条目 TREE-01、TREE-02、TREE-03、BASE-02；消费者 #21（A/B 回放）、#22（p2）

验证证据（2026-11-25 收口复核）：实现与测试见 doc/evidence/acceptance/、doc/evidence/framework/、doc/evidence/assembly/；状态由 TASK-QA-03 复核后更新。

## 背景

`modified-star` 是四扩展点中最后一个插件实现，也是唯一有状态的装饰器。框架已提供只读 `TreeRow`/`ReadonlyDocument` 投影、七类已提交事件与 `PluginContext.subscribe`（暂存订阅由宿主在注册提交后接入）、以及按注册顺序拼接后缀的 `TreePresenter`。本 ADR 固定 dirty 语义、指纹来源、祖先传播、删除与保存失败规则、标签顺序和事件接入方式，避免在 core/renderer 中加入插件分支。

## 决策

### 1. 基准与语义

- 采用“内容与最近一次成功保存/读入的基准不同”语义，而不是“发生过编辑命令”。
- 基准是**内容投影**：最近一次成功 `documentInitialized`、`documentRead`、`documentSaved` 事件携带的文档。`init` 生成的空文档因此是干净基准；`read` 建立新基准；成功 `save` 更新基准。
- 编辑、undo、redo、canvas 事件**不**更新基准，只改变当前文档；渲染时重新比较。
- 失败编辑/保存不发布事件，基准与当前文档都不变，因此失败不会产生或清除星号。
- `undo` 回到保存点时内容与基准相同（即使对象是新实例）→ 星号消失；`redo` 后重新出现。

### 2. 指纹来源

- 逐节点指纹来自公开领域投影：`id`、`tag`、`kind`、`textContent()`、父节点 id、有序子节点 id 列表，以及 `attributes()` 的快照（含 `data-kind` 等保留元数据、几何与样式；属性名排序以消除输出顺序影响）。
- 画布尺寸单独保存在基准中（它不是任一节点的属性），用于根行的画布变化。
- **不使用** XML 序列化字符串、运行期缓存、界面标签或 decorator 自身状态；相同内容重建、clone、undo/redo 得到相同指纹。属性顺序变化不产生误报。
- 指纹是实例内数据：每行 `decorate` 只返回自己的后缀，不读取其他插件状态。

### 3. 差异集合与祖先传播

1. 当前节点指纹与基准不同 → 该节点标星（叶子修改、几何/样式变化、文本变化、父节点变化、子节点顺序/成员变化）。
2. 基准中存在而当前缺失的节点（删除）→ 从**基准父链**向上标记其旧祖先；被删节点自身没有行，不渲染。
3. 对上述所有脏节点沿**当前父链**向上标记祖先，直到根行；因此叶子变化、插入、删除、重排都会让祖先与根行出现 `*`。
4. 当前画布尺寸与基准不同 → 根行标星（即使没有节点变化）。
5. 根行使用 `document.root`（`TreeRow.node` 即画布根）；根不是任何节点的子行，但通过祖先传播参与。

### 4. 标签顺序、实例与兼容

- 注册顺序决定后缀顺序；默认装配按 `box-type-label` → `modified-star` 注册，行为为 `g#n1 (box) *`，每个非空后缀前恰好一个空格。`modified-star` 不感知 `(box)`，box 装饰器也不读取 dirty 状态。
- 所有基准、缓存与差异集合都是 `ModifiedStarDecorator` 实例字段，不使用模块全局变量；两个编辑器/两个装饰器实例互不影响。
- 零装饰器或装饰器干净时，`tree`/`show` 与基线逐字节相同；禁用本插件后不产生任何后缀。
- 缓存键是“当前文档对象 + 基准版本”：文档快照不可变，编辑后对象身份变化自然失效；`init/read/save` 更新基准时递增版本，避免同一对象复用旧差异集合。

### 5. 事件接入方式

- `ModifiedStarPlugin.activate` 在暂存 `context` 上注册装饰器实例，并调用 `context.subscribe(event => decorator.onEvent(event))`。宿主在注册提交成功后连接该订阅；激活失败或清单不符时随暂存区丢弃，不会遗留监听器。
- 不要求组合根在安装后调用 `TreePresenter.connect`：`apps/cli` 的 `TreePresenter` 在 builtins 安装时创建并持有同一 live `TreeDecoratorRegistry`，后续插件注册的装饰器自然可见；事件由插件的暂存订阅转发，符合“插件激活只通过宿主暂存上下文注册能力和订阅”的约束。
- 装饰器读取 `TreeRow.document` 的只读投影，不持有活文档、不改历史或屏障；展示失败由 `TreePresenter` 隔离并禁用该实例。

## 备选与取舍

- **“发生过编辑命令”语义**：实现简单，但 undo 回到保存点不会清星，与课程要求的“内容与保存基准比较”不符；拒绝。
- **维护“被修改 id 集合”而不是内容比较**：无法区分“编辑后又改回原值”、undo/redo 与重建内容；拒绝。
- **每行单独计算或模块级缓存**：行间重复计算且可能跨实例泄漏；选择实例字段 + 单文档缓存。
- **XML 字符串指纹**：缩进、属性输出顺序、插件元数据都会造成误报；拒绝。
- **组合根统一 `TreePresenter.connect`**：F 的 `createApplication` 不向调用方暴露 presenter，且该调用应在所有插件安装成功后进行；插件暂存订阅是宿主已提供、可回滚的正式路径，选择后者。
- **删除节点自身的 id 进入差异集合**：没有对应行；选择只标记旧父链。

## 验证

真实执行（详见 [020-tree-01 验收证据](../evidence/acceptance/020-tree-01.md)）：

- `@svgframe/tree-modified` 26 项单测：指纹内容性（重建/属性顺序/文本/父节点/子节点顺序）、init/read/save 基准、新建/删除（叶子与整棵子树）/重排/跨容器移动/画布变化、祖先传播与旧父链、undo/redo 回保存点、失败编辑/保存、两实例隔离、双标签顺序与零字节。
- 根 `test/plugin-tree.test.ts` 6 项：CLI 下 create/save/move/undo/redo/set/undo 的星号序列、A/B 字节一致、禁用后无星号且回到无后缀字节、两个应用实例独立、失败编辑不改基准、box 与 modified 后缀顺序。
- `npm test` 128 项、`npm run test:packages` 298 项通过；A/B 同一 box 会话 stdout sha256 均为 `7F8A5CEF0D54205E6798587C3675C0F29F773F7D974C3A24B8AD82D83FC8582D`。
- 受保护路径 `packages/core`、`packages/host`、`packages/builtins`、`packages/svg-xml`、既有插件与渲染器差异为空。
