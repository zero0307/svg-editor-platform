# ADR-0001 保留历史初始化团队开发仓库

状态：Accepted  
日期：2026-11-15  
依据：维护者确认采用开发方案并授权初始化、整理文档和推送新仓库。

## 背景

六人团队将在 Phase 1 的 SVG CLI 基础上开发插件框架、VSCode 扩展和 DSH 插件。课程需要对比 `final` 与 `p2` 的代码及指标，并通过插件接入提交证明扩展性，因此必须保留原始对象、标签、作者和过程历史。

## 决策

- 使用 `zero0307/svg-editor-platform` 进行日常协作，从 `zero0307/svg-editor-cli` 的完整历史继续开发，不重新 `git init`。
- `final` 的标签对象和所指提交都保持原值；其他 Phase 1 归档标签同样保留。当前不创建 `p2` 或其他过程 tag。
- 空仓库导入允许将初始化提交直接推送 `main`；此后采用短期任务分支、PR 和 merge commit，保留课程过程。
- 按 F/C/B/T/V/D 板块与横向 Q 验收协作，目录和职责以 `doc/roadmap.md` 为唯一清单。
- 采用 npm workspaces 作为后续目标布局，当前不修改运行代码、依赖、现有测试和启动入口；工作区迁移另开任务。
- 把开发规范、原规格、架构、验收矩阵、ADR和过程模板纳入仓库。原 Phase 1 报告归档到同目录 `doc/phase1-report.md`，保持相对资源链接。
- 原课程仓库作为 `upstream`；最终验收版本与 `p2` 同步回原仓库，以符合任务书的同仓库交付要求。

## 取舍

新仓库便于团队管理，但增加最终引用同步工作。完整继承历史让兼容比较和指标可复现；不同时进行目录重构，使初始化差异可直接审查。分支保护、人员映射与远程CI不在本次导入中宣称已启用。

## 验证

核对原提交均为新主分支祖先、所有旧标签对象一致、`final^{commit}`不变、原运行目录无差异、归档报告原样保留。实际命令和结果见 [初始化记录](../initialization.md)。具体扩展接口与事务设计仍需后续ADR和契约PR，不因本条Accepted而视作已实现。
