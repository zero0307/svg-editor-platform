# SVG Editor Platform 开发方案

状态：总体方案已由团队维护者于 2026-11-15 确认采用。当前仓库继承 Phase 1 运行代码；Phase 2 工作区、插件与公共接口仍待实施。GitHub协作规则按 [配置记录](github-operations.md) 维护，人员映射在认领后补齐。

开发仓库：[zero0307/svg-editor-platform](https://github.com/zero0307/svg-editor-platform)。Phase 1 来源及最终课程交付仓库：[zero0307/svg-editor-cli](https://github.com/zero0307/svg-editor-cli)。

采用“保留历史的单仓库、多包、接口先行、分板块开发”的方案。在现有 Command、Composite、文档克隆事务和测试上渐进重构。先交付可验证的公共框架，再让命令、复合图形和树标签分别接入。VSCode 扩展可从第一天独立开发；DSH 先用替身完成工具逻辑，随后接入公开编辑服务。

## 关键约定

1. 保留 Phase 1 全部历史和 `final` 标签，开发结果最终同步回原仓库并打 `p2`。新仓库不重新初始化空历史。
2. 使用 npm workspaces、TypeScript strict、ESM 和现有 `node:test`；团队统一一个验证通过的 Node 24 补丁版本，且满足 DSH 当前要求的 Node >=24.9.0。现有依赖版本先保留，工作区改造另开提交。
3. 内核只依赖公开抽象；插件仅通过内核公开 API 注册能力、访问领域对象，不导入其他插件或宿主内部实现。
4. 四类扩展、文档事务、插件注册事务、通用图形恢复和结构保护，在框架阶段准备好。随后添加 `box`、命令、标签时不补内核分支。
5. `main` 配合短期功能分支；通过 PR 合并并保留过程提交。A/B 演示证据使用保留的专用分支和明确的提交 SHA。
6. 每个功能同时交付测试、对应需求条目和必要的文档更新；`doc/README.md` 是课程报告入口，`docs/metrics/` 按任务书保留原路径。

## 当前实施状态

仓库已从 Phase 1 完整历史开始初始化，保留全部旧标签。当前可运行布局仍为 `src/`、`test/`；`apps/`、`packages/`、`plugins/` 是下一阶段目标目录，尚未创建。原运行源码、测试和依赖保持原样。

开发规范、任务/PR模板、原始规格、方案、ADR清单与过程记录已纳入本仓库。初始化和验证事实见 [初始化记录](initialization.md)，后续任务见 [路线](roadmap.md)。正式接口设计需经契约PR和测试验证后落地，不能把本方案视作已实现的插件框架。
