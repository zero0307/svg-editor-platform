## 2. Issue #14 四条验收逐条结论

### 2.1 禁用所有可选插件时原 83 项及新增回归通过，基础会话与 final 相同 —— **通过**

证据：

- 根 `npm test` 92 项全绿。原有 7 个测试文件与断言保留（`acceptance`/`cli`/`commands`/`domain`/`strings`/`svg`/`transforms`，83 项），#1 的 6 项基线测试继续通过，新增 3 项组合根测试；合计 92。- `phase 1 golden replays byte-exactly against the current build` 以新入口 `apps/cli/dist/main.js` 重放四个会话，`compare.mjs` 输出 `4 sessions, 4 matched, 0 differed`；`dir` 会话仍是 `error: unknown command: dir` 且退出码 1，`basic`/`flowchart`/`io` 的 stdout/stderr/退出码/写出的 SVG 逐字节一致。
- 默认入口（A）在 `plugins.config.json` 为空时不加载任何可选插件，默认能力仅来自 builtins 安装。

### 2.2 六种图形 / 全部原命令 / help 可用，参数和未知命令/图形错误不变 —— **通过**

证据：

- 六种 `ShapeProvider` 与 19 条 `Command` 均注册；`test/domain.test.ts`、`commands.test.ts`、`svg.test.ts`、`transforms.test.ts`、`strings.test.ts` 全部原断言通过，覆盖几何、摘要、属性白名单、读写、嵌套/变换、失败原子性。
- `help` 由注册顺序生成命令 usage + provider usage + quote/EOF 两行；golden 会话中的 `help` 输出字节匹配；`node apps/cli/dist/main.js --help` 退出码 0。
- 未知命令 `error: unknown command: <name>`、未知图形 `error: unknown shape type: <type> (is the plugin loaded?)`、参数错误 `usage: <command>`、`no document...`、`undo not allowed after io command` 等 P1 文案由原测试与 golden 复核。
- `canvas` 仍为“无参数 query / 带参数 document”；`create ... in <id>` 的带引号 `in` 语义由 `CommandToken`/`prepareTokens` 保留，原测试 `quoted in text is not a container clause` 通过。

### 2.3 默认 A/B 输出相同且内置实现经过同一校验路径 —— **通过**

证据：

- `test/composition.test.ts` 的 `composition roots A and B produce byte-identical output without plugins`：同一临时 cwd、同一 stdin 会话分别运行默认入口（A）与 `--config plugins.config.json`（B），`status` 均为 1，`stdout`/`stderr` 字符串完全相等。
- `createApplication` 先构造 live 注册表/`ProviderShapeCreationService`/`XmlSvgCodec`/`EditorSession`/`PluginInstaller`，再用同一 installer 安装 `BuiltinsPlugin`（manifest 声明 6 种图形 + 19 条命令）；测试断言 `results[0].ok === true` 且注册命令数 19。A 的可选模块列表与 B 的 `PluginLoader.loadFromConfig` 都追加在同一 installer 之后，加载器不 import 具体插件。
- B 的 `--config` 省略路径时默认根 `plugins.config.json`；根文件为 `{"plugins":[]}`。

### 2.4 core 不导入 builtins 或具体命令/图形，旧新两套运行内核不并存 —— **通过**

证据：
