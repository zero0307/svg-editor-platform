## 4. 逐条对照 Issue #20 验收标准

| #   | 验收标准                                                                | 结论 | 证据                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 编辑→保存→再编辑→undo 回保存点清星，再 redo 恢复，失败编辑/保存不改基准 | 通过 | 根测试 CLI 序列：create 后全星 → save 后无星 → move 后星 → undo 回保存点无星 → redo 星；`set fill` 后星、undo 回 moved 状态仍有星、再 undo 回保存点无星。`ModifiedStarDecorator.test.ts` 覆盖 undo/redo 回保存点；根测试「失败编辑不改基准」用非法 `set`/`move missing` 后 tree 保持干净            |
| 2   | 覆盖 init/read、新建/删除/重排/画布变化及祖先传播，ADR 明确规则         | 通过 | `ContentSnapshot.test.ts` 6 项（内容指纹、属性顺序、文本/父节点/子节点顺序、差异集合、box 元数据）；`ModifiedStarDecorator.test.ts` 覆盖 init/read/save、叶子与整树删除（旧父链）、重排、跨容器移动、画布变化（仅根行）、新建、祖先传播；规则见 [ADR-0015](../../adr/0015-dirty-semantics.md) §1–§3 |
| 3   | 两个编辑器/标签实例不泄漏，双标签互不感知且顺序固定                     | 通过 | 插件测试「two decorator instances keep independent baselines」；根测试「two application instances keep independent dirty state」；双标签行 `g#n1 (box) *`（box 先、modified 后、各一个空格），插件测试用测试替身 box 标签验证顺序，根测试用真实 box 插件验证                                        |
| 4   | 禁用后 tree 回基线字节，接入不改内核/renderer                           | 通过 | B 配置 `tree-modified enabled:false`：`tree` 输出与干净状态逐字节相同且全输出无 `*`；插件测试「clean modified decorator contributes no bytes」；受保护路径差异为空；渲染器/`TreePresenter` 未改                                                                                                     |

## 6. 差距与后续

1. **事件接入方式**：`apps/cli` 未在组合根调用 `TreePresenter.connect`；本插件通过宿主提供的暂存 `context.subscribe` 接收事件（安装提交后连接、失败回滚），符合框架暂存契约，未改 core/CLI。
2. dirty 状态不持久化：每个 CLI 进程/编辑器实例以最近一次 `init`/`read`/`save` 为基准；重新启动进程不保留“未保存”星号。这是内容比较语义的直接结果，已写入 ADR-0015。
3. 独立 `C_A`/`C_B` 证据分支与完整 A/B 回放属 `#21`；本节点在同一提交内验证 A/B 输出逐字节一致。
4. 仅本机 Windows + Node v26.13.0 实跑；未在 Node 22/24、Linux/macOS 或 CI 执行；`npm run verify:visual` 与本节点无关，未重跑。
5. `#19` box transcript 的插件集固定说明见 §2；`#21` 回放时应分别使用「Phase 1 空配置」「box 时代插件集」「默认四插件」三种装配，避免把标签后缀差异当成回归。
