## 3. 输出格式与参数规则

```text
rect: 2  circle: 1  text: 1  (total 4, containers 1)
```

- 从画布根子节点按当前顺序 DFS；叶子按 `kind` 计数，类型按首次出现排序；`g`、`box`（以及任何公开 `ContainerShape`）只计 containers；根 SVG 不计；容器内叶子照常统计；`total` 为叶子总数。
- 空文档输出 `(total 0, containers 0)`；只有空容器时输出 `(total 0, containers 1)`。
- `stats` 不接受参数。规格未规定参数错误文案，本节点选最保守方案：沿用 Phase 1 `CommandArguments` 的 `usage: <usage>`，即输出 `error: usage: stats`，与既有命令一致。
- 效果声明为 `query`：只拿到只读投影，不进入历史、不改变文档、dirty 基准与 I/O 屏障。

统计样例（`artifacts/stats-evidence/session.txt`，未提交）：

```text
init 800 600
create rect r1 0 0 10 20 red
create g g1
create circle c1 5 5 3 in g1
create text t1 1 1 "hi"
create rect r2 0 0 1 1
stats
help
```

## 6. 差距与后续

1. **dirty 状态暂无框架 API**：F 只提供 `documentInitialized/read/saved`、`editCommitted`、`undo/redoCommitted`、`canvasChanged` 事件，dirty 语义由 `#20`（modified-star）建立。本节点能证明的是：`stats` 是 `query`，不调用 session、不产生事件、不改文档与历史，因此不会建立或清除任何 dirty 基准；待 `#20` 接入后由组合级测试复核。
2. **C_A/C_B 证据分支未建立**：本节点在同一提交内验证 A（代码装配）与 B（配置装配）的注册表与输出一致；课程要求的独立 `C_A`/`C_B` 差异证据由 `#21` 统一建立。
3. `doc/transcript/stats-dir.txt` 未创建：Issue 规划该文件同时覆盖 stats 与 dir 的固定会话，`dir` 命令属 `#18`，届时一次补齐并交给 `#21` 回放。
4. 仅在本机 Windows + Node v26.13.0 实跑；未在 Node 22/24、Linux/macOS 或 CI 上执行；`npm run verify:visual` 与本节点无关，未重跑。
5. `npm install` 输出提示两个既有依赖的 install script 被策略拦截（`@vscode/vsce-sign`、`esbuild`），与本节点无关，`npm run check` 不受影响。
