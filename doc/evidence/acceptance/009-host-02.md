# Issue #9（TASK-HOST-02）验收证据

被测分支：`team/yi-eng`；本节点提交为 `feat(host): add file and directory adapters (#9)`，提交 SHA 见交付报告；证据来自该提交前的真实工作树。环境：Windows、Node `v26.13.0`、npm `12.2.1`、TypeScript `7.0.2`。

## 1. 临时目录覆盖普通项/隐藏项/空目录/特殊项/不存在路径，资源 finally 清理

`packages/host/test/directory-reader.test.ts` 通过（13 项 host 测试中的 7 项）：

- 普通文件、隐藏文件 `.hidden.svg`、子目录 `nested`、中文与空格名称 `中文 空格.txt` 都出现在直接子项中；`nested/child.txt` 不出现，证明不递归。
- 空目录返回 `[]`。
- 不存在路径与“把文件当目录”两种情况都报 `cannot read directory: <path>`，且后续测试可继续执行。
- 符号链接测试在本机真实创建成功（文件 symlink；若失败会回退 junction，再失败才 `t.skip` 并写明原因），结果为 `kind: 'link'`，且未跟随链接。证据记录：本机该测试实际执行，不是跳过。
- 所有测试使用 `mkdtemp(os.tmpdir())` 并把清理放在 `t.after`，`fs.rm` 带 `force/maxRetries/retryDelay` 容错，避免 Windows 句柄占用导致残留。
- `other`（FIFO/设备等）在 Windows 无通用创建方式，只有代码分支（`kindOf` 末行），未做真实条目测试；这是本节点明确的覆盖缺口，留给 #18 的真实目录组合或 Unix CI 补。

## 2. 保存原子替换和失败清理保留，不破坏原文件

`packages/host/test/file-store.test.ts` 通过（6 项）：

- 读取 UTF-8 文件返回原文；读取不存在文件报 `cannot read file: <path>`。
- 写入新文件后内容正确且目录中无 `*.tmp` 残留。
- 已存在文件被替换为新内容，无临时文件残留。
- 目标路径是已存在目录时，写入报 `cannot write file: <path>`，该目录仍存在，父目录无临时文件残留。该失败路径真实触发了 Windows 重试（测试耗时约 200ms，5 次上限后返回原错误），随后清理临时文件。
- 目标父目录不存在时，写入报同一文案，父目录未被创建，无临时文件残留。
- 适配器对 `EPERM`/`EACCES`/`EBUSY` 做有上限退避重试（10/20/40/80ms，最多 5 次），重试耗尽后仍抛 Phase 1 原文案，不吞错误、不改变目标文件。

## 3. 测试不并行 process.chdir，日志与被列目录隔离

- `LocalDirectoryReader` 的 cwd 通过构造参数注入（默认 `() => process.cwd()`），测试验证 `cwd()` 返回值与 `process.cwd()` 在调用列表前后不变；没有任何 `process.chdir` 调用。
- 每个测试使用独立的 `mkdtemp` 目录，测试日志只输出到 stdout/stderr，不写入被列目录，因此目录内容不受日志影响。
- `npm test` 的文件级并行不会相互改变 cwd 或目录。

## 4. 真实适配器可替换，core/业务插件无 Node 文件系统导入

- core 只暴露 `FileStore` 与 `DirectoryReader` 端口接口；`packages/core` 源码不 import `node:*`（架构检查规则强制）。
- host 适配器只实现端口；`packages/host/index.ts` 导出 `LocalFileStore` 与 `LocalDirectoryReader`，dir 插件后续只依赖 core 端口，可在测试中用 `FakeDirectoryReader` 替换。
- `node scripts/check-architecture.mjs` 通过：5 个 workspace、88 个源文件、4 条跨包 import，host 只依赖 `@svgframe/core`。
- 说明：`packages/core/ports/FileStore.ts` 与 `packages/core/index.ts` 的导出是本框架节点按负责人授权补充的公开端口，未修改 core 既有语义；`DirectoryEntryKind` 沿用 core 已有的 `'link'`（不是 `'symlink'`），`#18` dir 插件应以 core 类型为准渲染 `[LINK]`。
