### 2.1 实际 Extension Host 中 SVG 旁显示 `[]`，文本文件和目录无标记 —— **通过**

- 真实宿主：VSCode 1.143.1，独立 profile（`--user-data-dir`/`--extensions-dir`/`--new-window`/`--disable-workspace-trust`）启动 Extension Development Host，未影响用户已有窗口。
- 激活证据（`exthost.log` 原文）：`Extension host with pid 23424 started` → `Eager extensions activated` → `ExtensionService#_doActivateExtension svgframe.vscode-svg, startup: false, activationEvent: 'onStartupFinished'`；日志无 `[error]`。
- 截图观察（[badge.png](../vscode/badge.png)）：`.hidden.svg`、`broken.svg`、`plain.svg` 行尾显示 `[]`；`plain.txt`、`README.md` 与 `.hidden`、`.vscode`、`nested` 目录无标记。
- 隔离 profile 的 `window.zoomLevel=2` 仅用于放大文字便于辨认，不改被测代码。

### 2.2 前后文件名和内容不变，多目录/隐藏示例不会抛异常 —— **通过（有一处如实说明）**

- 扩展没有写文件能力：`src/` 中不含 `fs`/`workspace.fs.write*` 调用；判定层是纯函数；真实运行前后 `git status --porcelain` 均为空，示例文件未被改名或改写。
- 判定层单测覆盖目录、符号链接/其他类型、非 `file` scheme、退化路径，均返回无标记而**不抛异常**；Provider 对 `workspace.fs.stat` 的失败（条目消失、权限、远端 URI）捕获后返回 `undefined`，不向宿主抛错。
- 多目录与隐藏示例：`.hidden/`、`.vscode/`、`nested/` 三个目录在 Explorer 中正常渲染且无标记；点开头的 `.hidden.svg` 正常显示 `[]`。
- 如实说明：`.hidden/hidden.svg` 所在的隐藏目录**未在真实宿主中展开观察**（Explorer 中为收起状态）；该路径的判定由单测 `.hidden/canvas.svg` 覆盖，Provider 的异常吞并路径由代码审查确认，未把它写成“已实测展开”。
