# Issue #13（TASK-XML-02）验收证据

被测分支：`team/yi-eng`；本节点提交为 `feat(svg-xml): add provider-driven strict SVG codec (#13)`，提交 SHA 见交付报告；证据来自该提交前的真实工作树。环境：Windows、Node `v26.13.0`、npm `12.2.1`、TypeScript `7.0.2`。

说明：真实六种 builtins provider 属 #14，本节点用测试内 fake provider 独立验证通用恢复；Phase 1 的 83/89 项全量回归在 #14 用真实 provider 重跑，本节如实区分。

## 1. 原 SVG/字符串/变换测试和基线输出通过（本节点范围）

- 旧 `npm test` 仍 **89 项全绿**（运行旧 `src/` 实现，证明工程变更未破坏 Phase 1 基线）。
- 新 codec 用 fake provider 复刻 Phase 1 语义并逐项断言：
  - 六类元素（rect/circle/ellipse/line/text/g）decode → encode 与手工 P1 期望字符串逐字节相等，并再次往返稳定。
  - 缺失 ID 的编号顺序与警告文案逐字等于 P1：`rect2`/`g2`/`rect3`，三条 `warning: assigned id ... to unnamed <...>`。
  - 嵌套 `translate`/`scale` 的顺序、父级 `stroke-width`/`font-size` 继承、反向 `scale(.5)` 的复位、默认文本/描边尺寸物化、显式 `inherit` 均与 P1 测试期望一致。
  - 敏感属性缩放拒绝覆盖继承的 `stroke-dasharray`、`rect rx`、`font-size="2em"`。
  - encode 覆盖 XML 声明、2 空格缩进、属性顺序、`&`/`<` 转义、末尾换行、`px` 尺寸规范化与 CRLF 文本规范化。
- 与真实 builtins 的逐字节对照、真实 83 项迁移回归**未在本节点执行**，属 #14；本节点不能据此宣称 Phase 1 导入已整体迁移完成。

## 2. 每片叶子累计变换只应用一次，恢复容器后不二次变换整树

- 嵌套 `scale(2) translate(10,20)` 中 rect 几何为 `x=22 y=44 w=6 h=8`、circle `r=6`、ellipse `ry=8`、line `x2=26`、text `font-size=20`（与 P1 测试相同）。
- `translate(10 20) scale(2)` 的结果为 `x=12 y=24`，验证变换列表按 SVG 矩阵顺序合成。
- 复合 fake provider 的整体 `translate(5,5)` 只作用于子 rect 一次：子几何 `x=6 y=7`，没有出现 11/12 的双重变换。
- `SvgElementView.transform` 是元素的世界变换；测试中的叶 provider 手动 `scale` 再 `move`，容器 provider 明确不应用自身变换。

## 3. 重复 ID 在降级前拒绝，读入失败不改变文档、历史或默认路径

- `<g data-kind="fake-box"><rect id="x"/><circle id="x"/></g>` 在**未安装** fake-box provider 时仍先报 `id already exists: x`，证明重复检查先于任何降级/provider 分派。
- 深度超过 128 层报 `SVG nesting exceeds 128 levels`，同样先于恢复。
- 未知标签保持 P1 文案 `unknown shape type: <tag> (is the plugin loaded?)`；显式语义匹配与 tag 默认匹配的多命中分别报 `ambiguous provider match for <g>: ...`，不按注册顺序静默覆盖。
- 坏 provider（`restore` 抛 `incomplete fake-box`）使 `EditorSession.read` 拒绝，且 `session.document()` 仍是 read 前同一个对象；`EditorSession.read` 只在 `decode` 成功返回后才替换当前文档，因此历史与屏障也不会被半成品修改。

## 4. 假复合 provider 可完整恢复与往返，匹配冲突没有静默覆盖

- fake `data-kind="fake-box"` provider 通过 `ShapeRestoreService` 恢复完整子树，`kind === 'fake-box'`、子节点顺序保持；`document.clone()` 后仍是同一复合类型，encode 与克隆前逐字节相同。
- 未安装 box provider 时同一输入按 `g` 恢复且保留 `data-kind`（encode 中含该属性）；未知 `data-kind` 也按标签默认恢复并保留。
- CDATA 文本、`font-size`、`text-anchor` 等元数据在 decode/encode 往返中保留。
- 歧义测试通过第二个 box 匹配 provider 与第二个 `defaultTag="g"` provider 分别验证显式/默认两阶段都拒绝，而不是取第一个。
