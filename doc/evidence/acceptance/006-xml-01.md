# Issue #6（TASK-XML-01）验收证据

被测分支：`team/yi-eng`；本节点提交为 `feat(svg-xml): add neutral syntax entry with source ranges (#6)`，提交 SHA 见交付报告；证据来自该提交前的真实工作树。环境：Windows、Node `v26.13.0`、npm `12.2.1`、TypeScript `7.0.2`。

## 1. 嵌套根/容器/叶子、无 id、重复标签、同一行多元素的树与范围正确

`packages/svg-xml/test/syntax.test.ts` 覆盖并通过：

- 嵌套 `svg → g → rect/circle`：`outerSpan`/`startTagSpan`/`nameSpan` 切片与源码逐字符相等，父 span 包含子 span。
- `<svg><rect id="a"/><rect id="b"/><rect/></svg>`：三个同名兄弟独立定位，第二个 `rect` 的 span 从它自身的 `<` 开始，证明没有按标签文本搜索；无 id 元素得到 `id: undefined`。
- 重复标签三层嵌套 `<g id="one"><g id="two"><g id="three"/></g></g>`：按位置解析，不按文本匹配。
- 未知标签 `foreign:thing` 与嵌套 `<svg>`、`my-shape.two` 等名称原样保留；`<g id="b"></g >` 的结束标签空白也不影响范围。
- 文本元素 `<text>你好😀</text>` 的 `outerSpan` 与 `text` 正确；属性值含 `>`、单双引号时开始标签不被提前截断。

## 2. 中文/emoji、LF/CRLF、前导空白与 UTF-16 约定

- `SvgSyntaxSpan` 的公开注释写明：偏移为 **0-based UTF-16 code unit，start 含、end 不含**，不是字节偏移也不是行列；行/列与 VSCode `Range` 转换由 #11 适配器负责。
- 测试覆盖：前导 BOM 与空白、`\r\n` 换行、注释/DOCTYPE/XML 声明前置、多行开始标签、`<!-- 中文😀 -->` 前缀、`<text id="标题">内容 😀</text>`；span 切片与 JS 字符串长度一致，代理对按 2 个 code unit 计。
- 测试中的 CRLF 只出现在运行时字符串，未提交 CRLF 文件。

## 3. 不完整 XML 可由调用方显示空大纲，且没有未捕获异常

- API 返回判别联合 `{ ok: true; root } | { ok: false; message }`，`parse()` 内部捕获所有解析错误；调用方不需要 try/catch，可在 `ok:false` 时清空 Outline。
- 失败矩阵测试（逐项 `assert.doesNotThrow` + `ok === false` + 非空 message）：空串/纯空白/非 XML 文本/`<`/`<svg`/`<svg>`/未闭合子元素/结束标签不匹配/属性缺值/属性引号未闭合/注释未终止/CDATA 未终止/根后多余元素/未知声明/根后文本。
- 失败信息带 `invalid SVG syntax at offset N: ...`，便于 #11 记录而不暴露给用户。

## 4. 包不依赖 host、具体图形插件或 VSCode API

- `packages/svg-xml/package.json` 只有一个内部依赖 `@svgframe/core: "*"`（为 #13 预留，语法层本身目前不 import core 符号），没有 `@xmldom/xmldom` 等运行时依赖。
- `node scripts/check-architecture.mjs` 通过：svg-xml 未 import Node 内置模块、未跨包相对导入、包名/目录/声明一致。
