- 分支：`team/wu-dsh`

- 插件包：`apps/dsh-plugin/`
- 证据：`doc/evidence/dsh/README.md`、`doc/dsh.md`

## 验收逐条

### 1. 固定版本真实加载/工具调用/卸载成功，卸载无注册或监听残留

**部分满足（加载/注册/卸载已实测；模型侧调用未执行）。**

- 加载：临时 `DSH_HOME` 的 `wu-test` profile 组合中出现
  `# == @svgframe/dsh-plugin` 行，`--dump-config` 退出码 0。
- 注册：真实启动（`headless ping`）stdout 出现
  `registered svgframe_probe; registry=hit`。
- 卸载：进程退出时 `disposed svgframe_probe; registry-free=true`，
  即释放后 `ctx.tools.get()` 已无该注册；插件只注册工具与一个 `ctx.effect`
  清理函数，无其他监听。
- 未执行：模型侧真实工具调用。headless 需要 `DEEPSEEK_API_KEY`，本机无凭据，
  命令退出码 1（`MISSING_CREDENTIAL`），已如实记录，不以计划代替证据。

### 2. schema 和结果可 fake 独立测试，不启动 CLI 子进程或解析回显

**满足。** `apps/dsh-plugin/test/` 用 fake `ctx`（内存工具注册表）与
fake `EditorSessionPort` 覆盖：注册结构、输出 schema 与结果、卸载无残留、
取消传播、端口失败路径。`node --test test/*.test.js` 共 **7 项通过 / 0 失败**，
不启动任何 CLI 子进程，不解析终端文本。

### 3. 版本、安装命令、边界和恢复方法可复现，官方 API 差异有记录

**满足。** 见 `doc/dsh.md`：版本 0.2.2-rc.5、npm 同名版本、Node 24.21.0 实测、
临时 `DSH_HOME` 装配步骤、临时 profile 边界、删除即恢复、以及
`defineTool`/`parameters`/`output.schema`/`ctx.effect`/`DSH_INSTALL_DIR` 解析等差异；
未验证项（模型侧调用、`ctx.fs`、HMR、pnpm 流程）已单独标注"未验证"。

### 4. 第三部分验收歧义明确记录，不把市场发布列硬要求

**满足。** 歧义与口径记录于 `doc/dsh.md` 与本节：

- "真实加载"按"真实 DSH 宿主组合并执行 `apply`、工具进入宿主注册表"判定，
  不以市场/商店发布为准；本任务不做市场发布、UI 或模型后端（Issue 明确排除）。
- "工具调用"存在两种口径：(a) 宿主注册表可见；(b) 模型实际调用并产生结果。
  本任务达成 (a)，(b) 因无模型凭据未执行，记为待补，不算通过。
- "卸载"按同一进程内 effect 释放 + 注册表无残留判定；跨进程重启后的
  持久化残留不在本任务范围。
