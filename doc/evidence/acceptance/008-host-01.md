# Issue #8（TASK-HOST-01）验收证据

被测分支：`team/yi-eng`；本节点提交为 `feat(host): add shared plugin loader with staged rollback (#8)`，提交 SHA 见交付报告；证据来自该提交前的真实工作树。环境：Windows、Node `v26.13.0`、npm `12.2.1`、TypeScript `7.0.2`。

## 1. 四类规定失败、非法 default、重复注册、非法 JSON/结构、内部依赖与求值失败都有测试

`packages/host/test/plugin-installer.test.ts` 与 `plugin-loader.test.ts` 覆盖并通过：

- 四种规定失败：模块找不到（`plugin not found: ./missing/index.mjs`）、没有 default（`plugin has no default export: no-default`）、manifest 与注册不符（`plugin manifest mismatch: mismatch (declared: attributes=[], commands=[declared], decorators=[], shapes=[]; registered: attributes=[], commands=[actual], decorators=[], shapes=[])`）、activate 抛错（`plugin failed to activate: activate-throws (boom)`）。
- 非法 default 结构：`{ activate: 42 }` → `plugin failed to activate: bad-default (default export has no activate function)`。
- 重复注册：与既有全局名重复（`duplicate registration: commands/taken`）与插件内部重复（`duplicate registration: commands/alpha`）。
- 非法配置：JSON 语法错误与四种非法结构都返回 `invalid plugin config`，且没有部分加载。
- 内部依赖缺失/顶层求值抛错：均报 `plugin failed to activate: <name> (<reason>)`，不是 `plugin not found`；两者与真正的模块缺失在同一测试中对比。

## 2. 失败插件前后放成功插件：先前保留、四类注册与订阅零残留、后续可用

`rolls back every failure category between two good plugins` 一次运行覆盖 9 个失败插件，前后各一个成功插件：

- 结果顺序：before 成功 → 9 个失败（顺序与配置一致）→ after 成功；`host.commands.names()` 只含 `taken`、`after`。
- 四类注册表在失败后无残留（`shapeProviders`/`treeDecorators`/`attributeHandlers` 为空，commands 只有成功插件）。
- 失败插件的 `context.subscribe` 从未接入真实总线：`EditorEventBus.observerCount === 0`；`activate throws after subscribing` 用例中监听器未被回调。
- 每个失败结果都是结构化 `PluginInstallResult`，调用方继续下一个入口，不需要 try/catch。

## 3. enabled:false 不解析/求值/激活

`skips enabled:false without resolving or evaluating the module`：被禁用模块的顶层代码直接 `throw new Error('must not be imported')`；配置中前后各一个成功插件。结果只有两个成功项、无失败项，两个成功命令均注册，证明该模块没有被 import；否则会多出一条 activation failure。

## 4. 集合比较不吞重复名、错误文案准确、非法配置回退默认能力

- `compares declared names as a multiset`：`contributes.commands = ['alpha','alpha']` 而只注册一次时返回 manifest mismatch，声明里保留 `[alpha, alpha]`，没有被去重成集合后误判通过。
- 错误文案按 ADR-0011 冻结的表格逐字断言（含类别顺序 `attributes, commands, decorators, shapes` 与排序后的名称）。
- `rejects invalid JSON...` 与 `rejects invalid config structures...`：读文件/解析/结构校验失败一律 `invalid plugin config`，返回单个错误结果且注册表为空，组合根可据此保留默认内置能力。
- 重名错误文案 `duplicate registration: commands/taken` 与课程规定一致；重复在发布前拒绝，全局表仍只有前一个插件的一项。

## 5. A/B 共用注册校验入口，加载器不 import 具体插件

- `PluginLoader` 只依赖 `PluginInstaller`、配置解析/规范化与 Node 文件解析；所有插件最终调用 `installer.install`。`PluginInstaller.installAll` 是 A 的入口，测试 `A and B produce identical results and registrations` 用同一组插件比较 B 的 `loadFromConfig` 与 A 的 `installAll`：结果消息与注册表名称逐项相同。
- 加载器源码没有具体插件 import、插件名映射表或按名称分支；模块通过配置字符串动态解析和 import。
- 组合根契约：四张注册表、`ShapeCreationService`、`DirectoryReader`、`EditorEvents` 由 #14 注入；全部成功后组合根再调用 `TreePresenter.connect`。

## core 契约映射说明

- `PluginContext` 增加 `subscribe(listener: EditorEventListener): () => void`（仅已提交编辑事件，类型化；ADR-0003 的“不提供任意事件总线”限制不变），`FakePluginContext` 同步实现并提供 `publish` 供插件单测；这是本框架节点按负责人要求补充的公开契约，未改既有注册/命令/会话语义。
- 插件包 manifest 的 `svgframe.contributes`（`shapes`/`commands`/`decorators`/`attributes`）映射到 core `PluginManifest.contributes` 的 `attributeHandlers`；A 也可直接传 core 形状，规范化结果一致。
