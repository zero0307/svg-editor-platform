## 验收逐条

### 1. 有效输入生成带矩形/文字/连接线的可读 SVG，检查输出稳定

**满足（业务层，fake gateway + 真实 codec/builtins）。**

- `svg_create_flowchart` 用 core `SvgDocument` + builtins 六类 provider +
  `XmlSvgCodec.encode` 生成节点 `<rect>`、标签 `<text>`、连接线 `<line>`；
  样例 [flowchart-example.svg](../dsh/flowchart-example.svg) 为 3 节点 2 连线，
  共 8 个元素。
- 生成结果能被 `svg_inspect` 用严格 codec 回读：元素数、种类计数
  （`{rect:2, line:1, text:2}`）与根子节点顺序稳定；同一文件两次检查结果 `deepEqual`。
- 未执行项：**模型侧真实调用**（无 `DEEPSEEK_API_KEY`），见第 4 条。

### 2. 非法参数/读写失败明确报错且不污染后续调用，多会话不串文档

**满足（业务层）。**

- 空 `path`、重复节点 id、未知边端点、非正尺寸、resolve/read/write 失败均抛
  `DomainError`，测试断言了消息。
- 失败后同一工具再次调用成功；两次创建分别写 `one.svg`/`two.svg`，内容互不含对方
  节点，模块级无可变文档；每次调用新建 `SvgRuntime`。
- 取消信号在读写前生效（`aborted`），失败不写文件。

### 3. 无 workspace 链接的干净目录可安装、执行两个工具和卸载，记录版本命令产物

**部分满足。** 干净目录安装、真实宿主加载/注册/卸载已实测：

- 仅复制 `package.json` + `cordis.patch.yml` + `dist/plugin.js`（292147 字节，
  sha256 `51A45A…B2FB3`）到 `%TEMP%\dsh-wu-16\install`，仓库外 Node 直接
  `import()` 成功，证明产物内联了 `@svgframe/*` 与 XML DOM，不依赖 workspace 软链。
- 临时 profile 的 `--dump-config` 出现 `# == @svgframe/dsh-plugin`；
  `headless ping` stdout 为
  `registered svg_inspect, svg_create_flowchart` / `disposed; registry-residue=none`。
- 退出码：dump/create 为 0；boot 为 1，原因是 `MISSING_CREDENTIAL`（无模型凭据），
  非插件失败。
- 未满足部分：**两个工具在真实宿主中的模型侧执行未完成**（无凭据），
  因此"执行两个工具"只在业务层（fake gateway + 真实 codec）验证。

### 4. fake 测试独立运行，真实装配使用相同业务逻辑并提供真实会话证据

**部分满足。**

- `apps/dsh-plugin` 的 19 项测试全部通过（`npm test -w apps/dsh-plugin`），
  用 fake `SvgFileGateway` 与 fake `ctx`，不启动 CLI 子进程、不解析终端文本；
  生成/检查逻辑与真实装配是同一份 `src/` 代码。
- 真实装配证据：bundle 由真实 DSH 宿主加载、两个工具注册并释放（日志原文见
  `install/boot.log`）。
- 差距：真实会话中的模型调用缺 `DEEPSEEK_API_KEY`，未执行；不把"宿主注册成功"
  写成"真实会话调用成功"。

## 歧义记录

- "执行两个工具"有两种口径：(a) 工具在真实宿主注册表可执行；(b) 模型在真实会话中
  实际调用并得到结果。本任务达成 (a) 与业务层执行，(b) 记为待补。
- "独立安装"按"不依赖 workspace 软链、产物自包含"判定，不要求市场上架；Issue 明确
  排除市场发布。
- 自环边（`from == to`）未禁止，渲染为长度 0 的 `<line>`；无业务约束要求报错。
