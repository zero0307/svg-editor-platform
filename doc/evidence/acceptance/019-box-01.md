## 3. 会话输出样例（实测）

```text
svg> create box n1 120 100 160 60 "开始"
g#n1 created
svg> tree
svg (800x600)
└── g#flowchart
    ├── g#n1 (box)
    │   ├── rect#n1-rect  x=120 y=100 w=160 h=60 fill=#4a90d9
    │   └── text#n1-label  (140,135) "开始"
    ├── g#n2 (box)
    │   ├── rect#n2-rect  x=520 y=100 w=160 h=60 fill=#f5a623
    │   └── text#n2-label  (540,135) "处理数据"
    └── line#arrow1  (280,130) -> (520,130) stroke=black
svg> set n2 fill #f5a623
box#n2 fill propagated to n2-rect
svg> set n2 label "处理数据 v2"
box#n2 label updated: "处理数据 v2"
```

help 的 Types 末尾追加 `  box <id> <x> <y> <w> <h> "label"`（A/B 各一次）。

**与 P1 示例的已知偏差（框架缺口，见 ADR-0014 §7）**：create/move/delete 反馈使用 `shape.tag`，实际为 `g#n1 created`、`g#n2 moved by (0,100)`、`g#n1 deleted`，P1 §6.1B 示例为 `box#…`；undo 为框架统一的 `undone: <message>`；`ungroup box` 实际为 `cannot ungroup box: n1`，P1 §4.4 原文为 `cannot ungroup composite shape: n1`。功能语义一致，期望 transscript 按当前框架字节冻结。

## 6. 差距与后续

1. **命令反馈多态钩子缺失（框架缺口）**：create/move/delete 输出 `g#…` 而非 P1 示例的 `box#…`，create 无“子部件摘要”，undo 无自定义恢复文案。建议 #19 后独立框架补丁：core 公开多态描述钩子、builtins 动作改用、复核 ungroup 文案；补丁合并后重跑并更新 transcript。
2. **ungroup 文案**：框架固定 `cannot ungroup box: n1`，与 P1 §4.4 的 `cannot ungroup composite shape: n1` 不同，功能拒绝行为一致。
3. dirty 语义由 `#20` 引入；本节点未提供 dirty API，box 的持久化元数据（`data-kind`）已包含在属性投影中，供 #20 指纹使用。
4. 独立 `C_A`/`C_B` 证据分支与完整 A/B 回放属 `#21`；本节点在同一提交内验证 A/B 注册表、help 与输出一致。
5. 仅本机 Windows + Node v26.13.0 实跑；未在 Node 22/24、Linux/macOS 或 CI 执行；`npm run verify:visual` 与本节点无关，未重跑。
6. 中文标签/名称的编码与 `data-kind` 顺序由既有 codec 保证；本节点未新增编码器分支。
